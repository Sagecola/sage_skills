# 文件分类规则

## 核心判断逻辑

**问自己一个问题**：「这个东西做完之后，我会移到别的地方吗？」
- 会 → 30_Projects（项目）
- 不会，它本身就是终点 → 50_Assets（资产）

如果用户的归档根目录已经存在，先观察已有结构。已有稳定习惯优先于内置默认路径：

```text
用户当前明确指令 > 用户已有目录习惯 > 内置分类规则
```

例如用户已经使用 `31_Work/客户名/项目名/`，新的工作项目文件也应优先放进同样层级，而不是重新发明一个更“标准”的路径。

## 分类优先级

从上往下判断，命中即停：

| 优先级 | 判断条件 | 归属 | 典型文件 |
|--------|----------|------|----------|
| 1 | 证件/合同/证书 | 10_Identity | 身份证、护照、劳动合同、毕业证 |
| 2 | 持续维护的事务 | 20_Areas | 账单、报税、健身记录、签证 |
| 3 | 工作项目相关 | 30_Projects/31_Work | 项目文档、会议纪要、工作数据 |
| 4 | 副业相关 | 30_Projects/32_Side_Hustle | 副业项目文件 |
| 5 | 个人进行中的事 | 30_Projects/33_Personal | 代码、写作草稿、旅行策划 |
| 6 | 参考资料/学习资源 | 40_Knowledge | 教程、论文、书籍、模板 |
| 7 | 已完成的作品/记录 | 50_Assets | 日记、公益记录、AI作品 |
| 8 | 软件/工具/安装包 | 50_Assets/53_Software_Backup | 安装包、配置备份 |
| 9 | 已失效/完成的历史 | 99_Archive | 归档项目、过期文件 |
| 10 | 以上都不确定 | 00_Inbox | 先存着，问用户 |

## 置信度标注

分类输出时给每个文件标注置信度，方便用户快速审核：

| 置信度 | 使用条件 | 处理方式 |
|---|---|---|
| 高 | 文件内容或文件名明确指向某类，例如“身份证”“劳动合同”“体检报告” | 可进入移动计划，但仍需用户确认批量操作 |
| 中 | 能判断大类，但缺少项目名、年份、归属人等细节 | 列入计划，同时在“需要确认”里提问 |
| 低 | 只能根据扩展名或模糊文件名猜测 | 放入 `00_Inbox` 或暂不移动，询问用户 |

不要为了让分类表看起来完整而把低置信度文件强行归类。

## 隐私与敏感文件

遇到以下文件时，只读取判断所需的最小信息：

- 身份证、护照、户口本、驾照、结婚证
- 合同、协议、离职证明、劳动材料
- 病历、体检报告、疫苗记录、保险单
- 银行、社保、公积金、房产、车辆材料

回复中不要复述身份证号、银行卡号、手机号、详细住址、病情描述、合同金额等敏感细节。只说明“这是证件类文件”“这是医疗记录”“这是合同材料”即可。

## 各区域详细说明

### 10_Identity（身份基石）

**这是什么**：与「你是谁」相关的文件。丢了会很麻烦的东西。

**包含**：
- 11_Legal：身份证、护照、户口本、驾照、电子签名
- 12_Education：毕业证、学位证、成绩单
- 13_Career：简历、劳动合同、离职证明、职称证书
- 14_Health：体检报告、病历、疫苗接种记录、保险单
- 15_Finance：银行卡信息、社保公积金、房产车辆证明
- 16_Relationships：结婚证、家庭成员证件

**判断标准**：如果这个文件丢了，需要去政府部门补办，就放这里。

### 20_Areas（责任领域）

**这是什么**：持续在做的事，没有截止日期，需要定期维护。

**包含**：
- 21_Finance_Mgmt：报税记录、年度账单、投资跟踪
- 22_Health_Mgmt：健身计划、饮食记录、医疗账单
- 23_Housing_Mgmt：房租/房贷、物业通知、水电费账单
- 24_Career_Dev：年度述职、学习笔记、行业动态
- 25_Family_Life：签证、子女教育、家庭旅行计划、设备保修

**判断标准**：这件事需要定期（每周/每月/每年）回顾或更新吗？

### 30_Projects（行动项目）

**这是什么**：正在做的事，有明确目标和截止日期。

**包含**：
- 31_Work：主要工作，按项目建子文件夹
- 32_Side_Hustle：副业项目
- 33_Personal：个人项目（代码、写作、旅行策划、学习计划等）

**判断标准**：这件事有终点吗？做完会归档吗？→ 是 = 项目

**生命周期**：项目完成后，归档到 99_Archive 或移入 50_Assets。

### 40_Knowledge（知识金库）

**这是什么**：参考资料、学习资源、模板。不直接产生行动，但有参考价值。

**包含**：
- 41_Vaults：笔记软件数据（Obsidian Vault 等，保持完整结构）
- 42_Library：静态资料（Books/Papers/Reports/Courses）
- 43_Templates：简历模板、PPT 模板、代码片段
- 教程、论文、书籍、说明书

**判断标准**：这是用来「参考」的，还是用来「做事」的？参考 = 知识，做事 = 项目。

### 50_Assets（数字资产）

**这是什么**：做完的东西，持续积累，没有截止日。

**包含**：
- 51_Media：照片（按年份）、影视、音乐
- 52_Creations：个人作品（日记、公益记录、AI作品等）
- 53_Software_Backup：软件配置备份、字体、许可证

**判断标准**：这件事做完后，我会移到别的地方吗？不会，它本身就是终点 = 资产。

### 99_Archive（历史档案馆）

**这是什么**：已经完成或失效的文件。封存即历史，不要动。

**判断标准**：这件事已经结束了吗？这个文件已经没用了但想留着？

## 常见混淆场景

| 场景 | 应该放哪 | 理由 |
|------|----------|------|
| 正在写的代码 | 33_Personal | 进行中，是项目 |
| 已完成的代码作品 | 52_Creations | 完成品，是资产 |
| 公司年报（参考用） | 40_Knowledge | 参考资料 |
| 自己写的年度总结 | 31_Work | 工作文档 |
| 别人的教程 | 40_Knowledge | 学习资源 |
| 自己写的教程 | 52_Creations 或 33_Personal | 看是否还在更新 |
| 体检报告 | 10_Identity/14_Health | 身份基石 |
| 健身打卡记录 | 20_Areas/22_Health_Mgmt | 持续事务 |
| 下载的安装包 | 50_Assets/53_Software_Backup | 软件资产 |
| 正在安装的软件 | 先放 00_Inbox | 装完再归类 |

## 子文件夹命名建议

当目标区域需要项目名或主题名但无法从文件推断时，不要编造名称：

- 工作项目：`30_Projects/31_Work/{项目名}/`
- 副业项目：`30_Projects/32_Side_Hustle/{项目名}/`
- 个人项目：`30_Projects/33_Personal/{项目名}/`
- 照片视频：`50_Assets/51_Media/{年份}/` 或 `50_Assets/51_Media/{年份}/{月份}/`
- 资料库：`40_Knowledge/42_Library/{主题}/`

如果缺少 `{项目名}`、`{主题}`、`{年份}`，在分类表的“需要确认”列中提问。

## 二次整理场景

当用户只是新增少量文件或调整少量文件时，不要重新盘点整个档案馆。只需要：

1. 看新增文件本身。
2. 看相关目标区域的现有子文件夹。
3. 抽样查看同类文件命名。
4. 给出最小变更建议。

如果发现用户已有目录与内置规则略有不同，输出时写成：

```text
我看到你现有结构是 `40_Knowledge/论文/水处理/`，所以这篇水处理论文建议继续放这里。
按内置规则也可以放到 `40_Knowledge/42_Library/水处理/`，但为了保持一致，我优先沿用你的现有结构。
```
