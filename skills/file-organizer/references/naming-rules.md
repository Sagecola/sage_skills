# 命名规则详解

## 完整格式

```
YYYYMMDD_文档类型_核心标题[_v版本号][#标签][@归属][&备注].扩展名
```

## 字段说明

### YYYYMMDD（必填）

8 位日期，便于排序。用文件的创建日期或内容相关日期。

- 证件类：用签发日期
- 合同类：用签署日期
- 报告类：用完成日期或覆盖时段
- 素材类：用获取日期

如果内容里没有明确日期，按以下顺序选择：

1. 用户在当前对话提供的日期
2. 文件内容中的签署、发布、完成、开具日期
3. 文件修改日期
4. 今天日期

使用第 3 或第 4 种时，在说明里写清楚“日期按文件修改日期/今天日期暂定”。

### 文档类型（必填）

必须从控制词表中选择，不允许自创。

| 类别 | 可用类型 | 使用场景 |
|------|----------|----------|
| 凭证与财务 | 发票、小票、账单、保单、回执 | 报销、财务记录、保险 |
| 法务与身份 | 证件、合同、协议、证书、公文、证明 | 身份证明、法律文件 |
| 思考与产出 | 方案、纪要、报告、文稿、笔记 | 工作文档、个人思考 |
| 资料与输入 | 教程、论文、书籍、说明书、素材、标准 | 参考资料、学习资源 |
| 生活与事务 | 门票、行程单、清单、病历、通知 | 生活记录、出行、事务提醒 |

**选择原则**：
- 优先用大类（用「合同」而非「劳动合同」）
- 根据使用目的命名（门票用于报销→「发票」，用于纪念→「门票」）
- 不按文件名字面词机械选择。文件名里有“报告”，不代表文档类型一定是「报告」。

### 文档类型判定补充

按文件的使用目的和档案属性选择控制词：

| 文件场景 | 应选文档类型 | 不要误选 |
|---|---|---|
| 体检报告、检查报告、化验单、病历材料 | 病历 | 报告 |
| 劳动合同、租房合同、购买合同 | 合同 | 协议、文稿 |
| 身份证、护照、户口本、驾照 | 证件 | 素材、图片 |
| 毕业证、学位证、资格证 | 证书 | 证件 |
| 在职证明、收入证明、无犯罪记录证明 | 证明 | 证书、证件 |
| 会议记录、项目会议要点 | 纪要 | 笔记 |
| 项目总结、年度总结、调研结论 | 报告 | 文稿 |
| 物业通知、学校通知、公司公告 | 通知 | 报告、文稿 |
| 学术论文、期刊论文 | 论文 | 研报、教程 |
| 行业标准、国标 | 标准 | 说明书、研报 |
| 门票用于报销 | 发票 | 门票 |
| 门票用于纪念收藏 | 门票 | 发票 |

如果不确定文档类型，先在重命名计划中标为“需确认”，不要自创类型，也不要随便从控制词表里挑一个看起来接近的词。

### 核心标题（必填）

简洁描述内容，子主题用 `.` 分隔。

**好的标题**：
- `入职劳动合同` — 简洁明了
- `项目进展.第一阶段` — 用 . 分隔子主题
- `COD.影响因素` — 专业术语保留

**坏的标题**：
- `合同_入职劳动合同` — 与文档类型重复
- `2026年5月做的关于COD影响因素的实验数据分析报告` — 太长
- `新建文件夹` — 无意义

### _v版本号（可选）

需要版本管理时使用，保留 `_v` 前缀。

- `_v1.0` — 第一版
- `_v2.1.3` — 语义化版本
- `_v2` — 简单版本

**什么时候用**：
- 合同初稿/终稿
- 方案迭代
- 报告修订

如果原文件名或内容里有明确版本号，如 `v2`、`第二版`、`修订版3`，应转成 `_v2.0`、`_v3.0` 等规范格式。  
如果只有“最终版”“定稿”这类状态，没有数字版本，优先放到 `&备注`，如 `&终稿`，不要硬编 `_v1.0`。

### #标签（可选）

补充分类，可多个，每个独立用 `#`。

- `#折线图` — 图表类型
- `#带误差棒` — 格式特征
- `#工作` — 主题分类

**格式**：`#标签1#标签2`（不是 `#标签1标签2`）

**什么时候用**：
- 图表或数据特征明确：`#折线图`、`#柱状图`、`#带误差棒`
- 主题检索价值高：`#水处理`、`#报销`、`#旅行`
- 文件跨多个场景，标签能帮助搜索

不要为了凑字段给每个文件都加标签。标签应该提高检索价值。

### @归属（可选）

相关人员、地点或工具。

- 人员：`@HR`、`@张经理`
- 地点：`@总部`、`@海城`
- 工具：`@kimi`、`@Claude`

**什么时候用**：
- 家庭成员或本人相关：`@妈妈`、`@爸爸`、`@本人`、`@孩子`
- 文件属于某个联系人、部门或机构：`@HR`、`@张经理`、`@医院`、`@学校`
- 文件属于某个地点：`@上海`、`@总部`
- 文件由某个工具生成：`@Claude`、`@GPT`

例如：妈妈的体检报告可以命名为 `20260528_病历_体检报告@妈妈.pdf`。  
如果归属人明确，优先使用 `@归属`，不要把归属硬塞进核心标题里写成 `妈妈体检报告`。

### &备注（可选）

状态、特征或补充说明。

- 文件特征：`&带误差棒`、`&带偏差`
- 状态说明：`&待审批`、`&已归档`
- 来源说明：`&回访`、`&从xxx下载`

**多条备注**：用多个 `&` 分隔，如 `&回访&带误差棒`

**什么时候用**：
- 状态：`&终稿`、`&待审批`、`&已归档`
- 来源：`&回访`、`&官网下载`、`&扫描件`
- 特征：`&带误差棒`、`&带封面`

备注用于补充状态和特征，不要替代核心标题。

## 可选字段使用原则

`_v版本号`、`#标签`、`@归属`、`&备注` 是可选字段，不代表少用就是好。生成文件名时应逐项判断：

| 字段 | 有明确信息且有检索价值时 | 没有明确信息时 |
|---|---|---|
| `_v版本号` | 使用原文件或内容中的版本号 | 不编造版本号 |
| `#标签` | 用于主题、图表、报销、旅行等检索标签 | 不为了凑格式加标签 |
| `@归属` | 人员、地点、机构、工具明确时使用 | 不猜测归属 |
| `&备注` | 状态、来源、特征明确时使用 | 不添加空泛备注 |

输出重命名计划时，如果某个文件没有使用可选字段，可以在判断依据里说明“未发现明确归属/版本/备注”。

## 组合示例

### 简单（只用必填字段）

```
20250206_笔记_今天的思考.md
20240501_门票_周杰伦演唱会.pdf
20260601_清单_购物清单.xlsx
```

### 中等（加版本号或归属）

```
20260514_素材_水质检测.影响因素_v1.0@实验室.xlsx
20260519_报告_项目总结_v1.0@公司.md
20231216_合同_入职劳动合同_v1.0@HR.pdf
```

### 完整（所有字段都用）

```
20260519_素材_实验数据.消解时间_v1.0#折线图#柱状图@实验室&带误差棒.xlsx
20231216_合同_入职劳动合同_v1.0#工作@HR.pdf
20260528_报告_年度总结_v2.0#PPT@总部&带封面.pptx
```

## 文件系统限制

- NTFS 文件名上限 255 字符（中文每字 2 字节）
- 禁用字符：`/ \ | : " * ?`
- 核心标题力求精简，避免文件名过长

## 文件名清理

生成文件名时需要清理以下内容：

- 删除禁用字符：`/ \ | : " * ?`
- 把连续空格压缩为一个空格，通常再改为无空格的中文标题
- 去掉无意义词：`新建`、`最终最终`、`副本`、`扫描件1`（除非它确实区分版本）
- 不在文件名里写敏感号码，例如身份证号、银行卡号、完整手机号
- 文件名过长时，优先压缩核心标题，保留日期、文档类型和扩展名

## 常见错误

| 错误 | 问题 | 正确做法 |
|------|------|----------|
| `报告_项目报告` | 文档类型与标题重复 | `报告_项目进展.第一阶段` |
| `#折线图柱状图` | 多个标签没分开 | `#折线图#柱状图` |
| `劳动合同_入职合同_v1.0` | 用了小类而非大类 | `合同_入职劳动合同_v1.0` |
| `2026-05-28_报告_xxx` | 日期格式不对 | `20260528_报告_xxx` |
| `报告_xxx@HR@总部` | 多个归属没分开 | `报告_xxx@HR` |
