# 文件整理助手

帮助用户把杂乱文件整理进「人生档案馆」系统。核心目标是**好找、少打扰、不误动**，不是追求表面整齐。

这个 skill 是自包含的：除非用户在当前对话里明确给出自己的规则，否则使用本 skill 内置的文件夹架构、分类规则和命名规则。

## 工作原则

1. **先看后动**：扫描和分类阶段只读取、分析、展示方案，不移动、不重命名、不删除。
2. **用户确认后才执行**：批量移动、批量重命名、覆盖、删除都需要用户明确确认。
3. **不确定就问**：无法判断的文件放入 `00_Inbox` 或列入“需要确认”，不要强行归类。
4. **少读敏感内容**：证件、合同、病历、账单、保险、银行卡等文件只读取判断所需的最小信息；回复里不要复述身份证号、银行卡号、住址、病历细节等隐私。
5. **保持可逆性**：移动前保留原文件名和目标路径清单；发生重名时暂停处理该文件，询问用户选择覆盖、加版本号或跳过。
6. **跨平台执行**：在 Windows 用 PowerShell 命令；在 macOS/Linux 用 POSIX 命令。不要把示例命令机械复制到不匹配的环境。
7. **尊重既有秩序**：如果用户已经整理过一部分文件，后续建议应优先贴合现有目录和命名习惯，而不是机械套用内置规则。
8. **Windows 中文优先 UTF-8**：在 Windows 读取中文文件名、Markdown、TXT、CSV、JSON 时，优先显式使用 UTF-8；如果出现乱码，先用 UTF-8 重试，不要直接判断文件损坏。

## 内置文件夹架构

根目录由用户指定。常见选择：
- Windows：`D:\OneDrive`、`E:\`、`C:\Users\{用户名}\OneDrive`
- macOS：`~/Documents`、`~/Library/CloudStorage/OneDrive`

如果用户没有指定根目录，先问一句：`你希望把文件整理到哪个根目录？例如 D:\OneDrive 或 C:\Users\你\OneDrive。`

```text
{ROOT}/
├── 00_Inbox/               # 中转站：所有新文件先放这里，每周清空
├── 10_Identity/             # 身份基石
│   ├── 11_Legal/            # 身份证、护照、户口本、驾照、电子签名
│   ├── 12_Education/        # 毕业证、学位证、成绩单
│   ├── 13_Career/           # 简历、劳动合同、离职证明、职称证书
│   ├── 14_Health/           # 体检报告、病历、疫苗接种记录、保险单
│   ├── 15_Finance/          # 银行卡信息、社保公积金、房产车辆证明
│   └── 16_Relationships/    # 结婚证、家庭成员证件
├── 20_Areas/                # 责任领域：持续维护，无截止日期
│   ├── 21_Finance_Mgmt/     # 报税记录、年度账单、投资跟踪
│   ├── 22_Health_Mgmt/      # 健身计划、饮食记录、医疗账单
│   ├── 23_Housing_Mgmt/     # 房租/房贷、物业通知、水电费账单
│   ├── 24_Career_Dev/       # 年度述职、学习笔记、行业动态
│   └── 25_Family_Life/      # 签证、子女教育、家庭旅行计划、设备保修
├── 30_Projects/             # 行动项目：有目标和终点
│   ├── 31_Work/             # 主要工作，按项目建子文件夹
│   ├── 32_Side_Hustle/      # 副业项目
│   └── 33_Personal/         # 个人项目：代码、写作、旅行策划、学习计划等
├── 40_Knowledge/            # 知识金库
│   ├── 41_Vaults/           # 笔记软件数据，如 Obsidian Vault，保持完整
│   ├── 42_Library/          # 静态资料：Books/Papers/Reports/Courses
│   └── 43_Templates/        # 简历模板、PPT 模板、代码片段
├── 50_Assets/               # 数字资产
│   ├── 51_Media/            # 照片、视频、音乐、影视
│   ├── 52_Creations/        # 个人作品、日记、公益记录、AI 作品
│   └── 53_Software_Backup/  # 软件配置备份、字体、许可证、安装包
└── 99_Archive/              # 历史档案馆：已完成项目镜像、失效文件
```

核心原则：
- 分离动态与静态：`30_Projects` 是正在推进的事；`40_Knowledge`、`50_Assets`、`99_Archive` 是保存与参考。
- 不创建“其他”文件夹；不确定的东西进 `00_Inbox`，并告诉用户为什么不确定。

## 使用模式

| 用户意图 | 典型说法 | 应做动作 |
|---|---|---|
| 批量整理 | “整理这个文件夹”“Downloads 好乱”“扫描桌面” | 扫描 -> 读取 -> 分类计划 -> 等确认 -> 移动 |
| 单文件归档 | “这个 PDF 放哪”“这张图应该存哪” | 读取 -> 建议路径 -> 说明理由 |
| 单文件重命名 | “帮我按规则改名”“这个文件怎么命名” | 读取 -> 生成规范文件名 -> 可选执行 |
| 判断类型 | “这是什么文件”“这些截图算什么资料” | 读取或看文件名 -> 判断类型和用途 |

## 扫描深度策略

混乱目录通常包含软件项目、照片库、笔记库、备份目录、解压目录等。不要默认无限递归扫描。

默认采用广度优先：

1. 第一轮只扫描目标目录的一级内容：直接文件和直接子文件夹。
2. 对直接子文件夹先做摘要，不立刻全量读取：文件数量、扩展名分布、总大小、最近修改时间、少量文件名样本。
3. 默认最多深入到第 2 级。
4. 只有在用户明确要求、分类置信度低、文件夹名过于模糊，或用户确认继续时，才继续深入。

规模阈值：

| 情况 | 处理方式 |
|---|---|
| 30 个文件以内 | 可完整列出分类建议 |
| 超过 30 个文件 | 分批处理，每批确认后再继续 |
| 超过 200 个文件 | 先输出目录级摘要和建议批次，不逐个读取 |
| 超过 500 个文件 | 只做盘点和整理方案，等用户确认范围后再深入 |

常见不应默认深入的目录：
- 代码依赖：`node_modules`、`.venv`、`vendor`、`dist`、`build`
- 笔记库：Obsidian Vault、Logseq 图谱、知识库根目录
- 软件数据：`.git`、应用缓存、备份目录
- 大型媒体库：照片库、视频库、音乐库

如果用户确实要整理这些目录，先说明风险和范围，再按批次处理。

## 已有结构适配

首次整理时使用内置架构建立秩序。第二次、第三次或少量文件调整时，先观察用户已经形成的结构。

处理顺序：

1. 先扫描归档根目录的一级结构，确认是否已经存在 `00_Inbox`、`10_Identity`、`20_Areas` 等区域。
2. 查看相关目标区域的子文件夹命名习惯，例如 `31_Work/{客户}/{项目}`、`42_Library/{主题}`、`51_Media/{年份}/{月份}`。
3. 抽样查看同类文件的现有命名格式，优先沿用用户已经使用的格式。
4. 如果现有结构与内置规则冲突，明确指出差异，并询问用户沿用现有结构还是按内置规则调整。
5. 对少量新增文件，直接给出贴合现有结构的建议位置和命名建议；除非用户要求，不重新整理整个根目录。

判断优先级：

```text
用户当前明确指令 > 用户已有目录习惯 > 本 skill 内置规则
```

不要因为内置规则更“整齐”就改写用户已经稳定使用的结构。

## 批量整理流程

### 阶段一：扫描分类，只看不动

1. 确认目标文件夹和归档根目录。
2. 如果归档根目录已经存在，先查看现有一级结构和相关子文件夹习惯。
3. 按“扫描深度策略”列出目标文件夹内容，排除系统文件如 `desktop.ini`、`Thumbs.db`、`sync.ffs_db`。
4. 按扩展名读取或推断内容。读取策略见 `references/file-types.md`。
5. 按分类优先级判断目标位置。分类细则见 `references/classification.md`。
6. 输出分类计划，并等待用户确认。

分类计划必须包含这些字段：

```text
扫描完成，共发现 N 个文件。当前只是分类建议，尚未移动任何文件。

| 原文件名 | 建议位置 | 判断依据 | 置信度 | 需要确认 |
|---|---|---|---|---|
| 身份证扫描件.pdf | 10_Identity/11_Legal/ | 证件扫描件 | 高 | 否 |
| 项目数据.xlsx | 30_Projects/31_Work/{项目名}/ | 工作项目数据 | 中 | 需要确认项目名 |
| unknown.dat | 00_Inbox/ | 无法判断内容 | 低 | 需要用户说明 |

需要你确认：
1. `{项目名}` 应该叫什么？
2. `unknown.dat` 是什么文件？
3. 以上分类有没有要调整的？

确认后我再移动文件。
```

超过 30 个文件时，按类型或子文件夹分批展示，每批确认后再继续。

### 阶段二：确认后移动或复制

用户确认分类方案后，先确认操作模式，再执行。

操作模式：

| 模式 | 含义 | 适用场景 |
|---|---|---|
| 移动 | 把源文件移动到归档位置；源目录中被移走的文件不再保留 | 用户已经确认分类，希望真正整理干净 |
| 复制 | 把源文件复制到归档位置；源文件仍保留在原处 | 用户担心误操作，想先试运行或保留原始下载目录 |

如果用户没有明确选择，先问：

```text
你希望我执行“移动”还是“复制”？
- 移动：整理后源位置不再保留这些文件，空目录可清理
- 复制：源文件保留，适合先安全试运行
```

执行前检查：
- 目标文件夹不存在：创建。
- 目标位置已有同名文件：暂停该文件，问用户选择 `覆盖 / 加版本号 / 跳过`。
- 单个文件超过 500MB：提醒用户可能耗时或占用空间。
- 源路径和目标路径都要显示在执行清单中。

执行前必须输出移动计划清单，并再次等待确认：

```text
下面是移动计划，确认前不会执行任何操作。

| 操作 | 源路径 | 目标路径 | 冲突状态 | 备注 |
|---|---|---|---|---|
| move | C:\Users\me\Downloads\身份证扫描件.pdf | D:\OneDrive\10_Identity\11_Legal\身份证扫描件.pdf | 无冲突 | 证件类文件 |
| ask | C:\Users\me\Downloads\项目数据.xlsx | D:\OneDrive\30_Projects\31_Work\{项目名}\项目数据.xlsx | 需确认 | 缺少项目名 |
| skip | C:\Users\me\Downloads\unknown.dat | D:\OneDrive\00_Inbox\unknown.dat | 暂不移动 | 文件类型不明 |

需要确认后再执行：
1. `{项目名}` 应该叫什么？
2. `unknown.dat` 是否先放入 00_Inbox？
3. 是否按以上计划移动无冲突文件？
```

清单规则：
- `操作` 只能使用 `move`、`copy`、`rename`、`skip`、`ask`。
- `源路径` 和 `目标路径` 必须是完整路径，不能只写文件名。
- `冲突状态` 写 `无冲突`、`已存在同名文件`、`需确认`、`暂不移动`。
- 对 `需确认`、`已存在同名文件`、`暂不移动` 的文件，不要执行移动或复制。
- 用户只确认一部分时，只执行已确认的行。

Windows PowerShell 示例：

```powershell
New-Item -ItemType Directory -Force -Path "目标文件夹"
Move-Item -LiteralPath "源文件" -Destination "目标文件夹"
```

Windows PowerShell 复制示例：

```powershell
New-Item -ItemType Directory -Force -Path "目标文件夹"
Copy-Item -LiteralPath "源文件" -Destination "目标文件夹"
```

macOS/Linux 示例：

```bash
mkdir -p "目标文件夹"
mv "源文件" "目标文件夹/"
```

### 空目录清理

如果用户选择“移动”，本次操作可能让原有文件夹变成空目录。移动完成后可以清理这些空目录，但只清理**本次移动涉及的源目录**。

规则：
- 只删除空目录，不删除任何非空目录。
- 只处理本次移动清单里的源路径所在目录，以及这些目录向下的空子目录。
- 用户选择“复制”时，不清理源目录。
- 如果空目录位于明显重要的根目录，如 `Downloads`、`Desktop`、OneDrive 根目录，只报告“不清理根目录”。

清理前输出：

```text
以下目录在本次移动后已为空，可以清理：

| 空目录 | 处理 |
|---|---|
| C:\Users\me\Downloads\新建文件夹 | delete-empty-dir |

我只会删除这些空目录，不会删除任何非空目录。
```

Windows PowerShell 空目录清理示例：

```powershell
if (-not (Get-ChildItem -LiteralPath "空目录路径" -Force | Select-Object -First 1)) {
  Remove-Item -LiteralPath "空目录路径" -Force
}
```

完成后简短报告：

```text
操作完成：
- 已归档：17 个
- 跳过：1 个，原因：目标位置存在同名文件
- 暂存于 00_Inbox：1 个，原因：等待用户确认内容
```

### 阶段三：可选重命名

移动或复制完成后，必须询问用户是否需要统一重命名。不要默认开始重命名。

```text
文件已归位。需要我按命名规则统一重命名吗？
规则：YYYYMMDD_文档类型_核心标题.扩展名
示例：身份证扫描件.pdf -> 20260528_证件_身份证扫描件.pdf
```

用户同意后，先生成重命名计划，不直接执行：

```text
下面是重命名计划，确认前不会改任何文件名。

| 当前路径 | 建议新文件名 | 日期来源 | 文档类型 | 可选字段 | 判断依据 | 置信度 |
|---|---|---|---|---|---|---|
| D:\OneDrive\10_Identity\14_Health\妈妈体检.pdf | 20260528_病历_体检报告@妈妈.pdf | 文件内容日期 | 病历 | @妈妈 | 体检报告属于医疗记录，归属人为妈妈 | 高 |
| D:\OneDrive\31_Work\项目复盘最终版.docx | 20260601_报告_项目复盘&终稿.docx | 文件修改日期 | 报告 | &终稿 | 原文件名包含最终版 | 中 |

请确认：
1. 哪些文件名可以直接改？
2. `@妈妈`、`&终稿` 这类可选字段是否保留？
3. 有没有你想手动调整的文件名？
```

重命名执行规则：
- 用户确认前，不执行 `Rename-Item` 或任何实际改名。
- 用户只确认一部分时，只改已确认的文件。
- 目标文件名已存在时，暂停该文件，询问 `加版本号 / 跳过 / 手动指定名称`。
- 可选字段 `_v版本号`、`#标签`、`@归属`、`&备注` 不需要每个文件都用，但每个文件都要考虑是否有明确、有检索价值的信息可用。

命名规则见 `references/naming-rules.md`。

## 单文件流程

1. 读取文件内容或根据文件名推断；敏感文件只读必要信息。
2. 选择文档类型，必须来自控制词表：`发票、小票、账单、保单、回执、证件、合同、协议、证书、公文、证明、方案、纪要、报告、文稿、笔记、教程、论文、书籍、说明书、素材、标准、门票、行程单、清单、病历、通知`。
3. 判断存放路径。
4. 输出建议，不自动移动、不自动重命名，除非用户确认具体操作计划。

输出格式：

```text
建议文件名：`20260528_证件_身份证扫描件.pdf`
建议位置：`{ROOT}/10_Identity/11_Legal/`
判断依据：这是身份证明类文件，属于身份基石。
置信度：高
下一步：你确认后我可以生成移动或重命名计划。
```

## 命名速查

完整规则见 `references/naming-rules.md`。

```text
YYYYMMDD_文档类型_核心标题[_v版本号][#标签][@归属][&备注].扩展名
```

命名时：
- 日期用 8 位数字，如 `20260610`。
- 文档类型必须从控制词表选择，不自创。
- 核心标题要短，避免重复文档类型。
- 禁用文件名字符：`/ \ | : " * ?`。
- 不确定日期时，先用文件修改日期或获取日期，并在理由里说明。

## 常见判断

- 正在做的代码、写作、旅行规划 -> `30_Projects/33_Personal/`
- 已完成的代码作品、日记、AI 图片作品 -> `50_Assets/52_Creations/`
- 下载的教程、论文、报告、模板 -> `40_Knowledge/42_Library/` 或 `40_Knowledge/43_Templates/`
- 体检报告、病历、保险单 -> `10_Identity/14_Health/`
- 报税、账单、投资跟踪 -> `20_Areas/21_Finance_Mgmt/`
- 安装包、字体、许可证、软件配置备份 -> `50_Assets/53_Software_Backup/`

## 质量标准

一次合格的整理建议应该做到：
- 用户能看懂每个文件为什么放那里。
- 高风险操作都在确认后发生。
- 不确定项被明确标出，而不是被随便塞进某个目录。
- 文件名可排序、可搜索、不过长。
- 不泄露用户隐私内容。
